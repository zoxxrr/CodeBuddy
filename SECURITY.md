# Security Policy

Use the latest supported release. Please do not publish exploitable vulnerability details in public issues.

Report vulnerabilities privately to the repository maintainers with a description, reproduction steps, and potential impact. Do not include real user data.

The project uses password hashing, HTTP-only cookies, security headers, rate limits, and parameterized SQL. This does not replace deployment hardening, HTTPS, backups, dependency updates, and a security review before hosting real users.
